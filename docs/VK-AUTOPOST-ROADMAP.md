# Solar House VK — дорожная карта автоматизации

Обновлено: 19 ноября 2026. Это рабочие этапы, **не** календарные ограничения
на подготовку отдельных материалов.

## Принцип работы

1. Материалы готовятся пакетом на неделю: текст, медиа, подпись, время выхода.
2. Владелец согласовывает пакет целиком или отмечает отдельные правки.
3. Одобренные материалы ставятся в очередь; неопубликованные черновики не выходят.
4. Система загружает медиа, публикует по расписанию, проверяет результат
   и уведомляет об ошибках. Неопределённые попытки не повторяются вслепую.

Для видео разрешение на предварительную загрузку наступает **сразу после
согласования**. Время `publish_at` относится только к публикации на стене.
Предварительная загрузка в VK Видео может создавать черновик или запись в
видеокаталоге — точное поведение текущего интерфейса нужно подтвердить.

## Этапы и приёмка

### 1. Завершить первый видеотест — в работе

- Утверждённый 9-секундный MP4 сохранён в `media/`, хеш проверен.
- `Stage-VK-Video.ps1 -Upload` выбрал файл через Chrome от имени сообщества.
- VK Video обработал вертикальный 9-секундный файл **как клип**, присвоил
  `clip-211038294_456239559` и показал форму «Публикация клипа».
- Публикация не нажималась. Повторно загружать файл нельзя, пока не будет
  проверено, сохранился ли клип в черновиках.
- `Inspect-VK-Clip-Draft.ps1` выполняет безопасную сверку кабинета.
  Обнаружено, что вкладка «Черновики» не обязательно присутствует в списке
  клипов. Инспектор теперь фиксирует реальные элементы интерфейса и открывает
  только уже известную ссылку клипа для read-only проверки, не повторяет загрузку.
- Инспекция 19 ноября: в опубликованных по-прежнему 135 клипов, последний
  от 17 ноября; в «Отложенных» **0 клипов**, ID первого пробного клипа
  не обнаружен. Первая загрузка не завершилась нажатием «Опубликовать».
- Добавлен `Recover-VK-Terrace-Clip.ps1`: по умолчанию только проверка;
  `-Publish` допускает **ровно одну** новую попытку после сверки отчёта,
  оригинального журнала, локального MP4 и текущего списка ВК. Сохраняет
  второй журнал отдельно, не очищая первый, заполняет согласованное описание
  и нажимает публикацию максимум один раз. Любая неопределённость — остановка.
- Результат восстановительного запуска и наличие клипа на главной сообщества
  ещё нужно подтвердить на реальном Windows/VK; код не равнозначен публикации.
- После выбора файла программа не нажимает `Далее`, `Сохранить` и
  `Опубликовать`; сохраняет скриншот и журнал однократной попытки.
- Проверить, сохранился ли clip ID в черновиках, и выяснить настройки
  отложенной публикации, показа на главной и публикации в истории.
- Не подменять `clip-...` ожидаемым облачным `video-...`.
- Приёмка: подтверждённый ID **того же** клипа у сообщества, отсутствие
  нежелательной публикации на стене и отсутствие дублей.

### 2. Довести загрузку клипа и планирование до автоматических — следующий

- Автоматически заполнять описание и нужные настройки после
  загрузки, без ручного прохода по четырём шагам.
- Проверять принадлежность сообществу, приватность и конечный `clip-...` ID.
- Для коротких вертикальных роликов использовать проверенный путь VK Clips;
  не пытаться отправлять `clip-...` в старый облачный `wall.post`, который
  пока принимает только `video-...`.
- Не допускать двойной истории, если включена встроенная опция VK.
- Сохранять состояние до необратимого действия; неопределённые исходы
  блокировать для ручной сверки. Не повторять загрузку автоматически.
- Проверить способ запуска под интерактивной учётной записью Windows;
  GitHub Runner как служба **не гарантирует** доступность окна Chrome.
- Приёмка: два последовательных теста на разных одобренных материалах
  без ручных кликов и без дублей, с корректными community-owned ID.

### 3. Связать видеозагрузку с публикацией — после этапа 2

- Для клипов выбрать один проверенный механизм: отложенная публикация в
  кабинете VK Видео с контролем результата либо отдельный проверенный API.
- Подтвердить, создаёт ли опция «Показать на главной» запись на стене;
  не делать второй `wall.post`, если VK уже разместил клип.
- Отдельный облачный видео-publisher оставить выключенным до поддержки
  корректного типа вложения и сверки результата.
- Историю создавать ровно один раз: штатной опцией клипа **либо** отдельным
  story-workflow, после проверки соответствующей зависимости.
- Приёмка: нужный ролик на стене в срок, история после него, один пост,
  корректный журнал в GitHub. Допускается задержка запуска GitHub Actions.

- Согласовать рубрики, частоту постов/видео/историй, типы контента и
