# Solar House VK — дорожная карта автоматизации

Обновлено: 17 ноября 2026. Это рабочие этапы, **не** календарные ограничения
на подготовку отдельных материалов.

## Принцип работы

1. Материалы готовятся пакетом на неделю: текст, медиа, подпись, время выхода.
2. Владелец согласовывает пакет целиком или отмечает отдельные правки.
3. Одобренные материалы ставятся в очередь; неопубликованные черновики не выходят.
4. Система загружает медиа, публикует по расписанию, проверяет результат
   и уведомляет об ошибках. Неопределённые попытки не повторяются вслепую.

Для видео разрешение на предварительную загрузку наступает **сразу после
согласования**. Время `publish_at` относится только к публикации на стене.
Предварительная загрузка в VK Видео может создавать черновик или запись в
видеокаталоге — точное поведение текущего интерфейса нужно подтвердить.

## Этапы и приёмка

### 1. Завершить первый видеотест — в работе

- Утверждённый 9-секундный MP4 сохранён в `media/`, хеш проверен.
- `Stage-VK-Video.ps1 -Upload` выбирает файл через Chrome от имени сообщества.
- После выбора файла программа не нажимает `Далее`, `Сохранить` и
  `Опубликовать`; сохраняет скриншот и журнал однократной попытки.
- По результату выяснить форму метаданных, приватность, возможность
  черновика и получение community-owned `video-211038294_...`.
- Приёмка: подтверждённый ID **того же** видео у сообщества, отсутствие
  нежелательной публикации на стене и отсутствие дублей.

### 2. Довести браузерную видеозагрузку до автоматической — следующий

- Автоматически заполнять название/описание и нужные настройки после
  загрузки, без ручного прохода по четырём шагам.
- Проверять принадлежность сообществу, приватность и конечный ID.
- Сохранять состояние до необратимого действия; неопределённые исходы
  блокировать для ручной сверки. Не повторять загрузку автоматически.
- Проверить способ запуска под интерактивной учётной записью Windows;
  GitHub Runner как служба **не гарантирует** доступность окна Chrome.
- Приёмка: два последовательных теста на разных одобренных материалах
  без ручных кликов и без дублей, с корректными community-owned ID.

### 3. Связать видеозагрузку с облачной публикацией — после этапа 2

- Записать `video_attachment`, хеш файла и хеш подписи в очередь.
- Включать `VK_VIDEO_ENABLED` лишь после проверки staging и preview.
- `wall.post` запускать по `publish_at` с предварительным журналом,
  подтверждать ID и ссылку на опубликованный пост.
- Историю публиковать только после подтверждения связанного поста.
- Приёмка: нужный ролик на стене в срок, история после него, один пост,
  корректный журнал в GitHub. Допускается задержка запуска GitHub Actions.

### 4. Проверить текущие публикации — ближайшая приёмка

- Проверить пост и историю «Дом за миллион» на 18 ноября.
- Проверить ролик про террасу на 19 ноября в 10:00 МСК и историю в 10:15.
- При отказе или неопределённом ответе выяснять исход, **не** создавать
  повторную публикацию без сверки с ВК.

### 5. Недельный редакционный цикл — в проектировании

- Согласовать рубрики, частоту постов/видео/историй, типы контента и
  требования к визуалам Solar House.
- Готовить черновики на семь дней с реальными характеристиками проектов,
  без выдуманных цен и неподтверждённых обещаний.
- Сделать единый список `черновик → на согласовании → одобрено → опубликовано`.
- Предусмотреть согласование всей недели одним действием и правки отдельных
  материалов; публикация только после явного одобрения.
- Приёмка: пользователь утверждает пакет за один подход, затем система
  публикует без ежедневных команд PowerShell.

### 6. Генерация и мониторинг — после редакционного цикла

- Отдельно реализовать подготовку недельных черновиков по расписанию.
  Сейчас автоматическое создание **новых** постов ещё не подключено.
- Автоматическая сверка результата с ВК: ссылка, время, тип вложений,
  отсутствие дублей и отчёт об ошибках.
- Приёмка: недельный цикл проходит с одним согласованием и уведомлениями
  только о готовом пакете или реальной проблеме.

## Не включать преждевременно

- `VK_VIDEO_ENABLED=true` — пока не подтверждён staging видеозаписи.
- Автоматический повтор любых действий с неопределённым результатом.
- Фоновое открытие Chrome из Windows-службы до проверки интерактивной сессии.
